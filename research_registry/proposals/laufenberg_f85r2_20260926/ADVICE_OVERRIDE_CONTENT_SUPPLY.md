### The actual priority question

A proposed historical account would have to own, in writing:

1. The same patient/action and a generally stated timing recommendation.
2. The bodily condition, who judges it, and whether it requires, permits or merely favors earlier action.
3. A clause explaining whether the normal recommendation is defeated, inapplicable, suspended or still binding alongside the exception.
4. Any restrictions that survive urgency, their scope, and any later duty or return to the usual rule.

These are different semantic claims. Permission to act is not an obligation; advice against acting is not a prohibition; a recommended season is not a necessary precondition. No automatic conversion among these is supplied.

For example, **as an analyst illustration only**, let `U` mean a written urgency condition and `T` a favorable timing condition. A priority description saying “normally wait unless T, but act when U” can have exactly the same recommendation function as the ordinary partition `U -> act; not-U and T -> act; not-U and not-T -> wait`. Adding a third veto condition can likewise be expressed as a larger partition. Such a finite table by itself does not distinguish productive rule override from ordinary applicability. These are not source translations or proposed target values.

The serious rival is therefore a complete conditional partition with explicit owners and the same terminal actions, **not** a straw model that simply ignores the exception. A real next consequence would require source-written persistence: for example, a named rule remains generally in force, a specific duty survives permission, a later explicitly written return reuses the same rule, or a higher restriction blocks an otherwise valid exception. The Benedict descendant already provides one such persistence pattern. The pseudo-Bede lead might supply a different nested boundary, but it remains an unverified lead and even a three-level hierarchy can be extensionally equivalent to a partition.
