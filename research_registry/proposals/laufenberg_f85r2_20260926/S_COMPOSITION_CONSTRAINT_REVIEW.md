## Candidate laws: exactly what is or is not constrained

### A. Strict identity/deletion: a real conditional contradiction

If one hypothesizes that deleting e in `chey→chy` preserves denotation, the S lexicon requires an Event→TemporalGuard value to equal a ClauseCoordinator. Under the fixed typed grammar these are different signatures; this law fails. GDT914 records the visual edit but never licensed semantic identity. Likewise, null yp in ypshedy, null qod in qodaiin, null ol in oldar and the other null-extension readings in the table fail the fixed senses. Calling them “structural wrappers” does not erase this conflict.

This is a **contradiction of a newly added identity law with S**, not a contradiction of S derived from a confirmed manuscript morpheme. It adds no semantic winner for chey and no general deletion prohibition outside its stated contract.

### B. yp as regular opposition: three distinct proposals

Let H(x,r,t) be the already assigned adhesion state.

1. `yp(H) := NOT H` yields a state predicate, not the assigned sustained withdrawal EventNoun. Non-adherence also includes never having arrived or been presented; it does not entail motion away. Thus direct Boolean state negation has both a type and a content gap.
2. `yp(H) := CEASE(H)` or DETACH-from-H requires H before the departure. In the [typed clarification's](UNTIL_S_TYPED_CLARIFICATIONS.md) explicit counterworld, departure occurs in the same attempted cycle but no h₀/H token occurs. Requiring prior H in that cycle makes that specific non-vacuous departure witness impossible. This is a direct conditional semantic contradiction, not just a missing translation. Invoking an earlier, different adhesion episode would change the fixed cycle/owner contract.
3. An operator “sustained movement away from the location argument of H, whether or not H ever held” can produce the desired departure kind. It must explicitly project H's x/r arguments, introduce motion and sustained duration, and discard any presupposition of actual H. It is neither NOT nor CEASE. There is only **one complete yp+assigned-base example here**, and no independent yp production in the retained grammar. Encoding that desired mapping is possible but currently gives a one-pair construction with no held consequence or compression credit.

The source distinction matters: Galen III.1 discusses presented juice that keeps leaving before adhesion can occur. It does not require detachment from previously achieved adhesion. This supports rejecting the source-compatible interpretation of a mandatory prior-H rule; it does not identify yp.

### C. qod as a typed recipient-incorporating operator: one useful conditional restriction

This is a **candidate contract**, not a new accepted lexical entry or an edit to DRAFT.json. Choose the segmentation `qod | aiin` explicitly and temporarily hold it fixed. Define:

```text
QOD : Recipient → (Faculty × Substance → AttractionEventPredicate)
QOD(r)(f,x) := ATTRACT(f,x,Goal=r)

aiin : RecipientRef(r)
QOD(aiin) : Faculty × Substance → AttractionEventPredicate
```

Reference resolution from RecipientRef to its written r is the existing paragraph binder. This factorization preserves qodaiin's old ATTRACT sense. In S.16 the separately written `oteey` and `odain` supply f/x; `an` supplies the external toward-r phrase. Because r has already been incorporated, that external goal must agree with the incorporated r rather than overwrite it. This is a genuine same-goal condition under the candidate. In the current S interpretation it holds **by the authored binder**, not by a newly recovered observation.

The concrete typed consequence is:

```text
ain : LocativeRelation AT(r)
QOD(ain)  is ill-typed under Recipient-only QOD.
```

Therefore a candidate `qod | ain` analysis of the separately literal **qodain** would fail this rule unless one openly adds a lift. For example:

```text
LOC-OWNER : LocativeRelation → Recipient
LOC-OWNER(AT(r)) := r
```

That lift discards the at-location relation and extracts its owner. It is an additional construction, not a neutral spelling normalization. Nor does it by itself convert AT into a directed GOAL; the destination comes from QOD's separately chosen lexical valency. A rival that lets QOD take either Recipient or LocativeRelation requires a written overload and an account of the resulting goal. Declaring an arbitrary function for each input type to reproduce the desired answer is interpolation, not a constraint.

LOC-OWNER is well defined only if the accepted locative is represented as a tagged AT relation retaining its particular r, or an equivalent unique-owner property is independently specified. An arbitrary extensional location predicate has no automatic inverse returning a unique recipient. That representation/domain assumption is an additional cost beside the lift itself; no such inverse is silently introduced into the frozen grammar.

**Exact cost of this limited proposal:** one selected qod|aiin boundary; one new QOD semantic operator/signature; one ordered application rule; one incorporated-goal agreement condition with the already written `an`; a separate extension license before analysing qodain as qod|ain. An optional LOC-OWNER lift would be one further typed operation and a new claim about which locatives it accepts. It needs no additional whole gloss for qodaiin. It yields only one local composite training item in S; it is not yet a recurrent demonstration of the operator.

The candidate is more restrictive than an unrestricted unary lookup because it specifies admissible arguments, fixed output valency and agreement. It is **not entailed by GDT686**: the alternative qo|daiin boundary remains possible, and the reported qod family lacked a controlled multivalue context. qodain is not evaluated in this review; the owned projection and its complete W context were deliberately left unopened. Its unassigned IT alternative in S is also not a second independent manuscript observation.

### D. Shared argument labels or output classes: mostly insufficient

Calling every `ed` word “about r”, every `ar` word “part of the nourishment cycle”, or every ot word an Entity does not derive its fixed meaning. In particular r is a ubiquitous authored participant. Such labels neither recover the distinction between x and r references nor between arrival, adhesion and assimilation. A constant whole-output residual for each combination preserves any desired table. Even one uniform function over tagged syntax trees can inspect the whole tag and return its old gloss; reducing this to one function name does not reduce its information cost.

Mixed output sorts alone do not disprove morphology: a typed constructor can turn a noun into a predicate or an event into an agent. The missing requirement is a reusable, independently specified operation with a fixed signature and a consequence on another declared input. No such semantic operation is supplied by the formal component profiles.
