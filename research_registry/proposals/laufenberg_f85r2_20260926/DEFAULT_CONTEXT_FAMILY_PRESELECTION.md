## The necessary typed distinction

There are two importantly different proposals:

```
already evaluated base:       v = F(c_default, args)
context-indexed package:       Pack(F, realization=implicit)
```

One cannot recover F at a different context from v alone. Two kernels can agree at c_default and disagree at c_other, producing the same base value but incompatible new outputs. An arbitrary unary operation on v would need hidden information or a freely fitted extension. This is the same kind of information debt that makes a name-neutral descriptor unable to select a particular named participant.

The retained RAW instead proposes:

```
O(ImplicitPackage(F)) = ExplicitPackage(F)
bare use(a, env)      = F(env.current_context, a)
prefixed use(c, a)    = F(c, a)
```

The kernel, argument roles, subject and output type stay fixed. The extra context expression is written. The operation does not infer a context from an image, invert a predicate, change the default or introduce a new event. The package representation and two realization rules are extra commitments, not facts discovered from the string.

At page start the default is unbound. A future first contract must assign an overt context binder and its written context expression, a finite close/update policy, ordinary argument types, explicit reference resolution, and concrete definitions for all four base kernels. It must freeze all of this before the remaining dictionary. It cannot just label four unconstrained function tables F1–F4. A common typed context interface can be proposed; any tags, partial domains or higher-order operations are charged explicitly.

The first real consequence is conservation across **different** kernels, not equality of arbitrary function-input labels. When the written explicit context equals the active default, both realizations must yield the same kernel result. When it differs, only that argument changes. At least two distinct base families must actually exercise both modes with written input/context ownership. A later bare use must still use the previous default after an explicit o-use unless a separate written update appears. Without that later use, update and exposure remain observationally indistinguishable.

This is a potentially restrictive authored interface, not a demonstrated semantic result. Source-irrelevant tags cannot be appended merely to make two otherwise synonymous wholes different. No freely assigned meaning is allowed for the four derived outputs, and no root-specific branch or residual payload can secretly replace the common O operation.
