Two new proposed operator meanings would be `ol = ONSET_OF` and
`qokar = PRECEDES`. Two new cuts `ol|chedy` and `ol|shedy` would make joined
and separated expressions realize the same onset operation. Native spaces
and the GDT852 seam contrast do not establish those cuts or their semantics.
The alternative R/771 account gives separated and joined forms different
predication/restriction roles; X has not rejected it.

The type contract needed by this draft is explicit:

1. DAY is a **time-region**, not a physical body, a number of hours, or an
   interval automatically selected by the next dawn. Its membership predicate
   and FINISHED(C)'s state predicate may both enter the type TimePredicate.
   This two-case lifting is already present as GDT1025 B3; it is not new.
2. A common `ONSET_e(P)` would return the first false-to-true boundary of P
   inside one selected temporal window e, if such a boundary exists. The same
   operation must be used for DAY and FINISHED. An already true predicate at
   the left edge does not silently become a newly observed onset. Which
   window e is meant is **unbound**; one may not choose a new convenient day
   for each clause. Repeated days and repeated finishing are not counted.
3. PRECEDES would accept a temporal extent or point on each side and require
   end(left) < start(right). A point has equal start/end; this inclusion does
   not turn a point into a durative process. The proposed infix scope takes
   the nearest complete constructed expression, not automatically one group.
4. At IT .47 the new patient-before-action phrase rule would make
   `qokedy qokeedy` refer to a WEAVE event on the written cloth. Its worker
   could be the earlier written qoky at .45 G11 under a declared compatible
   participant rule. The first qokedy is .46 G4, followed immediately by
   another qokedy; identifying all three as one C is an assumption. The
   semantics of that repetition remain open.
5. FINISHED in .44/.45 precedes the first literal cloth. Its patient therefore
   remains unfilled under a strictly backward reference rule. Closing it with
   the later qokedy requires a separate, paid cataphoric paragraph rule; the
   draft does **not** report this identity as recovered. It also does not
   identify this C or W with the persons/artifact of f83r or the historical
   weaving narrative.
6. Treating the .47 WEAVE expression as a finite event with an endpoint, and
   treating final oldy as a temporal modifier of that same event, are further
   choices. A habitual activity type is not automatically a bounded event.

These are grouped construction costs, not a measured parameter count. No
hidden default translates the remaining words.

## What the draft derives, and what it does not

Conditional on those assumptions, .47 IT would say that a weaving event on
the cloth precedes a daytime onset; .45 and .48 would put a completion onset
and another onset on opposite written sides of the same infix relation.
This is a real proposed relation between arguments, more specific than
classifying both nouns as BODY, PERIOD or MATERIAL. It remains a partial C0
authoring step. Only one new qokar clause has substantial inherited content.

The first unregistered sketch used qokar=UNTIL. Under its specifically
process-valued signature, .48's proposed `[ol cheedy]` onset point would fail
as the left process without a new conversion. This is a **conditional type
objection to that sketch**, not a manuscript failure of UNTIL. An interval
or condition-taking UNTIL rival could have another signature. No registered
old test was changed in response.

ONSET(FINISHED) alone need not differ observably from the completion boundary
used by UNTIL(FINISHED). PRECEDES is stricter than an exact cessation-at-onset
claim, but no bound result time is written here in the current draft. Replacing
every proposed PRECEDES by FOLLOWS preserves the visible argument types. The
unknown yshey/otar/cheedy and unbound time window can still accommodate either
direction. Merely finding an onset-shaped phrase as the left argument does
not select temporal orientation. A NIGHT modifier does not identify which
day/night pair is at issue.

## Research decision

The novel authoring component is the explicit ol+condition rule with actual
arguments DAY and FINISHED and a third left-of-qokar occurrence. Its promise
does not survive as a decision-changing nomination yet: the new productive
rule appears in one complete unit, while the other owned unit expresses the
same temporal model through different, already freely guessed whole forms.
The two substantial rivals still differ only in unbound temporal relations.

Do not start a parser, simulator, new target acquisition or additional gloss
table for this draft. A useful continuation would need a concrete already
written construction that binds the missing direction/window/participant
relationship under the same rule, or a second whole context that actually
uses the proposed productive rule. This does not require independently
confirmed meanings before C0 authorship. It requires more than reassigning
the remaining temporal arguments to make one direction look natural.

No second weaker card is manufactured. The explicit partial draft stays
available in this dossier; existing RAW and failed routes remain unchanged.
