## Minimum argument frame

The source paragraph names different bearers and relations that a two-stage
`graded relation → greatest` composition must preserve. A usable symbolic
frame is:

```text
Planet = the seven-planet chapter domain
Person = a human recipient
Event e = one event of p, whose kind is BIRTH OR CONCEPTION
Power(q,e) = a degree/relation borne by planet q at e
RiseEast(q,e) = the explicit eastern-rise qualification
Gives(q,p,Properties(q),degree,profile?)
Profile(p,F) = properties received by p from a set of planet-donors
Share(q,p,F) = q's contribution to that same p/profile, if comparable
NameSource(p,F) = a contributor with greatest received properties
```

These are semantic argument labels, not a proposed lexicon or target
segmentation. `q` is a planet, `p` the human who holds/receives properties,
and `r` (if useful) the donor whose share is greatest. The source explicitly
says the planet identified as strongest gives the human its properties
according to its nature. Thus it licenses a contribution by that leading
planet. It does not turn a human into the bearer of planetary power, nor make
the set of power-bearing planets equal to the full donor set.

For the first comparison, retain one event reference `e` on the same generic
person `p`. The event-kind alternative is birth **or** conception. Rising in
the east and greatest power belong to the source's event-time frame; a
comparator must not silently substitute a later naming time or a different
person. The selected root decision requires the greatest-power condition,
not merely some high-power planet. It also chooses comparison over the
seven-planet domain and keeps the eastern-rise/great-power guard visible; the
exact source clause is not a modern ascendant algorithm.

For received properties, the comparison bearer is still a planet donor, but
the holder is the same human `p`. Compare candidate donors within a single
explicit profile `F(p)`. Do not compare one person's contribution against a
different person's, or use a total over planets as though the source had
specified arithmetic. The contributor domain is the actual donor support
for that profile; it is not automatically all seven, the set of power
leaders, or a set of seven zero-filled slots. The source's two/three/all
phrases give qualitative classes, not an exhaustive cardinality rule.

## What the source connects, and what it leaves open

The source supplies a real but qualitative dependence: the leading planet
gives properties according to its nature; the amount is expressed as much
as accords with strength. The root decision fixes strength's bearer as the
donor planet, while preserving the source's pronoun ambiguity as an
alternative. This supports a strength-dependent contribution, not a
calibrated function, ratio, linear transfer, common unit, or order-preserving
law across planetary strength and all the later received-property shares.
The operations must keep nature and strength as written dependencies, but
must not convert them into a numeric `Power = Share` identity.

The paragraph then says a planet rarely has power alone and that the human
has properties of more than one planet; it gives two, three, or all together,
with something little or much from each. Preserve the two claims separately:
sole **power** is an event-qualified condition, while multi-donor **receipt**
is a profile-support claim. `rarely` permits a sole-power case and is not a
hard lower bound on every support set. Conversely, “some” 2/3/all does not
make every human's profile contain every planet, or forbid counts 4–6.

The initial strongest planet `q` is an explicit donor, but the source does
not state that `q` is the sole donor, that every contributor held the
strongest power, or that `q` must be the later name-source. The name clause
selects from the planet “from whom” the same human has the most properties;
under that planet the person is born in that planet's day **or** hour. Keep
this name-source `r` within the profile support and bind both time branches
to the same `r` and the explicit birth. The final birth can equal `e` in the
birth branch; it is distinct from `e` in the conception branch. The paragraph
does not say that a conception-time profile is pooled into a natal profile
or that the initial power winner automatically satisfies the naming clause.

## Requirements for a legitimate greatest operation

1. **Respect stays explicit.** A greatest-power query must compare `Power`
   at one `e` over its declared planetary domain. A greatest-share query
   must compare donor shares in one `F(p)`. The operator may be reused, but
   the respect, owner, event/profile and candidate domain cannot be hidden
   lookup context.
2. **The result preserves a bearer.** The greatest operation must return the
   planet attaining the greatest relation (or an unresolved/tied result),
   not only a degree that loses the donor's identity and cannot fill the
   child/name role.
3. **Greatest means global greatest, not just maximal.** “Most powerful” and
   “most properties” ask for a value at least as great as every candidate in
   the comparison frame. A locally undominated/maximal planet in a partial
   order need not outrank an incomparable candidate. If the writing's
   comparison is not total, a greatest result may be unresolved; do not
   promote one maximal candidate with lexical order or position.
4. **No hidden tie-break.** The source uses singular forms but supplies no
   rule for equal greatest values. Preserve multiple co-greatest candidates
   or mark the case unresolved. Do not assign the unique winner as a free
   convention and then count it as source-derived.
5. **Composition must actually transfer the respect.** If the first
   operation lifts a graded relation and the second selects a greatest
   bearer, the same named comparison respect and same frame must flow into
   that comparison. A bare token lookup from a lexicalized whole to a planet
   does not demonstrate the source relation or its reuse on two distinct
   inputs.

## Small bridge-detection models

These are abstract checks on hidden assumptions, not historical natal cases.

**Power is not automatically the name-source.** Let `A` and `B` both be
contributors to one person's profile. Let `A` be the greatest at event-time
power, while the profile's explicit greatest-share relation selects `B`.
The source graph can represent the child attribution by `A`, a contribution
by `A`, and the mixed profile/name-source `B`, without identifying the two
comparisons. If an author rejects this model by making every power maximum
the share maximum, it has added an alignment bridge; the source's qualitative
strength dependency alone does not supply its full scope, units or temporal
identity. This toy assignment does not assert that historical contributors
had discordant rankings.

**Planet domain is not profile support.** Let the power frame range over all
seven planets, while the profile has contributors `{A,B}`. A greatest-share
query should compare `A` and `B` (or return unresolved if their shares cannot
be compared). Treating the other five as zero-valued donors or as eligible
name-sources changes the source's contributor relation. The “all together”
class is a different possible profile, not a global property of every human.

**Event OR is not event pooling.** Give the same person one birth event and
one conception event, and let the disjunctive source reference select one
event `e` for the initial strongest-power/child claim. A rule that requires
two child claims or sums both event profiles has expanded the OR. A rule that
globally deletes either branch has narrowed it. The later explicit birth
condition remains attached to the same name-source planet even when the
first event is conception.

These examples only show that owner/event/domain bridges are not logical
identities. They do not establish that the source requires different maxima,
that every modeled profile exists, or that any target reading contains the
relations.

## Review checklist for the later frozen author contract

The source-side pass can be satisfied without new source research if the
frozen contract makes explicit: (a) planet-vs-person argument types; (b) the
seven-member power domain versus profile donor support; (c) which planet
bears strength and how nature/strength condition giving without numerical
calibration; (d) the distinct rare-power and mixed-receipt claims; (e) one
birth-or-conception event variable for initial attribution, not two pooled
events or a deleted alternative; (f) a separately owned same-person birth
reference for naming; and (g) respect-preserving global greatest with honest
tie/incomparability behavior. A written type signature or comparison frame
is needed before “same operator” can mean actual reuse. Passing this checklist
would establish a source-compatible typed contract only, not a target meaning
or the truth of its assumptions.
