## Why this is more than renamed formal roles

The proposed meanings have an external truth condition. A fixed input and a
fixed algorithm determine every numeric result. The same decimal code must
encode a value whenever it recurs under another operation, and the same
operation must use the same prefix at every occurrence. The final record has
to satisfy exact arithmetic, not merely an incidence graph or a plausible
English gloss attached to each singleton word.

This does not make the writing convention historically established. It means
that the convention is a definite falsifiable hypothesis. One may provisionally
read an entire record as a calculation without already having a confirmed word,
provided all of that record is consumed and the whole set of conditional
solutions is retained. Arithmetic consistency constrains a meaning hypothesis;
it does not automatically identify the author's intended subject.

The reuse of real operations is essential. Separate private prefixes for every
phase would add unnecessary freedom. The root's sequence instead reuses SQUARE,
SUB, APPEND and MOD within a single record. Operand selection comes from one
fixed phase grammar, not a freely chosen address or a fresh interpretation for
each token. This is a much stronger contract than merely calling successive
positions input, action and output.

## The smallest reviewed contract

Freeze all inputs `100 <= n <= 9999`, exactly 9,900 positive three- or four-digit
integers. Every number uses canonical base-10 notation: zero is `0`, and there
are no leading zeros. The original input's last two digit positions are fixed
addresses: `b = floor(n/10) mod 10`, `c = n mod 10`. HIGH returns `a = floor(n/100)`.
For three-digit inputs a is one digit; for four-digit inputs it is two digits.

The two addressed input digits are already written within INPUT's numeral.
They are not claimed as separately written extraction instructions. APPEND
uses them directly at its fixed phases. This distinction is needed to make
the proposed 23-group format honest: it records the output of each declared
instruction, rather than pretending to display every arithmetic subexpression
used internally to evaluate an instruction.

Let `u = floor(sqrt(a))`, `s0 = a-u*u`, `d = 2*u`, and `w = 10*s0+b`.
The complete instruction sequence is:

| Position | Opcode | Numeric output or assertion |
|---:|---|---|
| 1 | INPUT | n |
| 2 | HIGH | a |
| 3 | ROOT | u, the integer root of a |
| 4 | SQUARE | u*u |
| 5 | SUB | s0 = a-u*u |
| 6 | DOUBLE | d = 2*u |
| 7 | APPEND | w = 10*s0+b |
| 8 | QUOTIENT | e = floor(w/d), the estimate |
| 9 | CHOOSE | k, the next root digit, as defined below |
| 10 | MUL | d*k |
| 11 | SUB | v = w-d*k |
| 12 | APPEND | z = 10*v+c |
| 13 | SQUARE | k*k |
| 14 | SUB | s = z-k*k |
| 15 | APPEND | r = 10*u+k |
| 16 | MOD | h = r mod 7 |
| 17 | SQUARE | h*h |
| 18 | MOD | j = (h*h) mod 7 |
| 19 | MOD | l = s mod 7 |
| 20 | ADD | q = j+l |
| 21 | MOD | q mod 7 |
| 22 | MOD | n mod 7 |
| 23 | CHECK | exact identity, remainder bound, and equality of the two proof residues |

There are 22 numeric-result instructions and one standalone CHECK, using
thirteen opcode types. SQUARE occurs three times, SUB three times, APPEND three
times and MOD five times. A single CHECK can assert all three terminal
conditions: `n = r*r+s`, `0 <= s <= 2*r`, and equality of positions 21 and 22.
The inferred values r*r and 2*r need not become additional written fields;
they are evaluations of the fixed assertion, not separately declared numeric
instructions. This is consistent with the source-side distinction between
written states and entailed verification equations.

CHOOSE must not mean the estimated quotient. Define it prospectively as the
greatest decimal digit `k in {0,...,9}` satisfying

```text
10*(w-d*k)+c-k*k >= 0.
```

This is a deterministic refinement of the source's trial-digit judgment. It
is not a claim that Fibonacci specified a descending search over all ten
digits. A generator may use `isqrt(n)-10*u` as an equivalent shortcut, but an
independent check should enumerate the ten digits and verify maximality. The
initial ROOT is a bounded integer-root operation on a between 1 and 99, as
distinct from silently obtaining the full final root as an unexplained input.
No rejected trial states are claimed as written unless the frozen language
explicitly adds such instructions; the current CHOOSE is one declared macro.

Modulo seven is a fixed semantic constant of MOD in this proposal. An extra
written modulus field is not required by its definition, but the source's
explicit mention of seven must not be represented as a decoded omitted word.
This is a generated program, not a transcription of all the Latin prose.

## Source fidelity and concrete countercases

The supplied [complete source dossier](ROOT_EXTRACTION_SOURCE_SUPPLY.md) gives
the actual 864 and 960 passages and describes the 12345 verification. It
distinguishes prose-named quantities from the table's placed digits. The
generated trace changes their presentation in a uniform, declared way:

- The table does not give separate rows for every intermediate named in the
  prose. This proposal explicitly writes every declared instruction's result.
- Some numeric outputs, such as the explicit cross product 36 and square 81
  in the 864 trace, are inferred computations. They are legitimate model
  outputs, not newly discovered literal source fields.
- Fixed phase addresses replace the source's instructions to put digits above
  or below particular input columns. In particular u is the tens digit of the
  final root, and k its units digit. Calling u the whole root would be wrong.
- Larger source examples invoke prior root results. Restricting the generated
  language to three/four-digit inputs yields the smallest single-extension
  program. It does not claim to reproduce all eleven examples' wording or to
  establish that larger inputs were absent historically.

The worked trace for 864 is fully determined:

```text
INPUT 864; HIGH 8; ROOT 2; SQUARE 4; SUB 4; DOUBLE 4;
APPEND 46; QUOTIENT 11; CHOOSE 9; MUL 36; SUB 10;
APPEND 104; SQUARE 81; SUB 23; APPEND 29;
MOD 1; SQUARE 1; MOD 1; MOD 2; ADD 3; MOD 3; MOD 3; CHECK.
```

This is a complete hypothetical numerical reading, not a claim to translate
an existing manuscript paragraph. The necessary checks include:

1. **Estimate is not digit.** For 864 the estimate is 11 and the chosen digit 9.
   For 960 the generated estimate is 1 and the chosen digit 0. Merely clipping
   the estimate to 9 is not a general selection rule.
2. **The remainder bound is non-strict.** For 960, r=30 and s=60. Excluding
   equality would reject an actual source example. Perfect squares likewise
   require permitting s=0 and retaining all zero-result instructions.
3. **The proof sum needs another reduction.** For n=105, r=10 and s=5. The
   reduced root-square contribution is 2 and the remainder contribution is 5.
   Their sum 7 must become 0 before comparison with `105 mod 7 = 0`.
4. **Modulo checking is insufficient by itself.** The incorrect pair r=22,
   s=23 for n=864 passes both `0 <= s <= 2*r` and the modulo-7 comparison,
   but `22*22+23 = 507`, not 864. The exact steps and identity exclude it.
5. **Print and witness are not one stream.** The dossier retains the 8171/8172
   printed-table discrepancy and manuscript comparison. The generated model
   must not pretend its mathematically correct outputs are a diplomatic repair.
   It includes each integer on its own terms: input 8171 gives remainder 71;
   input 8172 gives remainder 72, both with root 90.

A source-only enumeration of all 9,900 inputs, using the ten-digit CHOOSE
definition, verified the exact identity, non-strict bound, nonnegative residual
updates and modulo proof. The maximum quotient estimate was 14; the chosen
digit can be three below the estimate already clamped to 9. These are arithmetic
properties of this proposed source language, not manuscript observations.
The work's 1220 composition date remains distinct from the inspected witness's
catalogue dating only to the fifteenth century.

## Writing mechanism, free parameters and identifiability

Each numeric instruction is one whole group:
`opcode_string + encoded_canonical_decimal_result`. CHECK is its own whole
group. Every opcode has one global nonempty string, distinct from the other
opcode strings. The ten digits have distinct strings of one shared positive
width k. No phonetic alphabet, modern Arabic-digit glyph shapes, or historical
equal-width cipher convention is asserted.

The ordered phase grammar supplies the opcode and its operand addresses at
each position. Prefix overlap between opcode strings, or between opcode and
digit strings, therefore need not be prohibited globally. Nevertheless, all
complete candidate parses must be retained. Given n and k, each group's suffix
has the length dictated by that result's decimal length, and the remaining
prefix must equal the global opcode string. This gives a finite exact check;
it does not require a general-purpose decoder or unrestricted segmentation.

There are still substantial degrees of freedom: a choice of input for each
record, k, ten digit strings, and thirteen opcode strings. One occurrence of
an opcode does not independently identify its meaning. The repeated opcodes
inside each record and at least three **different inputs on three physical
leaves** under the same entire key supply the intended joint constraint. An
operation-specific digit alphabet, phase-specific spelling exception, selected
word deletion or change to the instruction order would destroy that contract.

Unused digits require distinct legal completions, and every such unobserved
completion remains unidentifiable. Distinct code components do not necessarily
make all whole groups globally distinct across different opcode contexts;
the fixed grammar, rather than a universal whole-word dictionary, resolves
their roles. Within an opcode, the injective digit code does require equal
numeric outputs to have equal full groups, and different outputs to differ.

Even a unique surviving assignment within this finite model would not prove
that all competing mathematical, linguistic or artificial models are false.
Do not collapse keys with different n/r/s readings into one semantic success
merely because they share some formal code pattern. A positive report should
publish complete decoded traces, full keys or explicitly arbitrary completions,
and every inequivalent interpretation surviving the declared bounds.

## Smallest adequate test and decision limits

First freeze this exact language, its source assumptions, the independently
audited source corrections, whole-record target ownership, and the shared-key
requirement. Then check fixed whole-frame eligibility and 23-group capacity
without changing the language in response to the result. Zero capacity stops
this writing contract before numeric fitting. It is not evidence against the
historical mathematics. No filler, optional-result, second-width or longer-input
variant should be added automatically to obtain capacity.

If capacity exists, enumerate all n/k cases per eligible complete frame,
require exact digit/opcode consistency, and join only under one unchanged key.
Report all single-frame cases as well as the joint result; isolated fits do not
satisfy the three-record hypothesis. Preserve nonliteral frames and computation
limits as unknown, and state exactly which scope has an exhaustive exclusion.
All observed keys should be applied unchanged to the remaining fixed intake;
no key extension may be silently chosen for its transfer success. The minimum
falsifier is failure of any necessary full-record/code condition, not a score
on selected equation-like fragments.
