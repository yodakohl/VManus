## Construction and binding accounting

The old grammar explicitly says one exact value-pattern per named clause,
twelve productions each observed once. Reusing that grammar means preserving
its actual pattern and semantics. Dropping words, permitting arbitrary intervening
material, changing argument order, or making optional slots is a new production
choice, not cost-free reuse of an old heading such as NAME_RULE.

For each of at most four new productions, the final offer needs an ordered
pattern, typed argument slots, scope/output, and a rule assigning every consumed
group. Count additional alternatives and hidden subproductions, not only top-level
labels. An unordered list of available forms plus a prose description cannot
determine a complete construction. A rule accepting arbitrary strings and then
looking up a whole sentence by position is a sentence macro. A new lexical entry
carrying several omitted predicates, participants or a whole result proof is
likewise not one ordinary whole-word value.

The six additional nondefault bindings must form an auditable list of actual
choices: antecedent, scope, parameter identity, source of derivation or endpoint.
One label bundling several independent equations does not turn them into one
binding. Conversely, a genuinely general production instantiated repeatedly
does not require one new exception for every mechanically derived argument.
Inherited bindings within unchanged P2 need not be recounted as new; extending
their scope to P1 is a new choice. Any further unlisted target-ID lookup, clause
exception, silent source reset, or coercion from numeral to ruler/unit is a cost.

GDT1039's seven-site iterator is not a free universal parser for this paragraph.
It factored selected P2 choices under explicitly supplied types and a registry.
Giving P1 new registry creation rules, a paragraph-wide reset policy, or a new
anaphoric domain requires an explicit extension and cost accounting.

## Cross-paragraph identity is additional content

Old P2 binds one H and common initial phase internally, uses the same successor
in C03/C08, and starts methods A/B from the same phase. It does not bind P1.

- H(P1)=H(P2), including order/direction, is an additional equality. Merely using
  the same NEXT_MEMBER value permits the same function on different orders.
- Sharing initial phase across paragraphs is another additional equality unless
  it follows from a declared written relation. Equal H does not imply equal phase.
- Equal generic DAY/HOUR meanings do not imply the same day, absolute hour,
  physical duration, or beginning/end event. Any such instance correspondence
  and chronology must be stated separately.
- A P1 endpoint becoming P2's beginning, a P2 explanation referring back to P1,
  and a retrospective description are different scope hypotheses. Physical
  adjacency or the shared picture does not choose among them.

Logical consequences of one stated equality should not be double-charged as
independent assumptions, but the offer must show which consequences are derived.
At least two independently written P1 statements must actually constrain a shared
time/phase/ruler argument. Asserting a shared alpha and then paraphrasing the old
24-mod-7 identity does not yet provide the newly required written dependency.
An endpoint function, relational constraint or comparison must be explicit enough
to tell an alternative assignment from the intended one. No solver is needed
to determine whether that contract has been supplied.
