## Explicit generative order

```text
PAGE/REGISTER
  -> RECORD TEMPLATE + LINE-ENTRY STATE
  -> FIELD SLOT / POSITION
  -> OPAQUE PAYLOAD FAMILY
  -> PAGE_HOST / GRAPHEMATIC KERNEL
  -> HOST×SLOT-CONDITIONED OUTER WRAPPER
  -> LOCAL O/OT FRAME + RIGHT-FAMILY RENDERING
  -> DY FIELD CLOSURE / B3-LIKE RECORD CLOSURE
  -> VISIBLE SOURCE GROUP
```

The operational probability order is:

```text
P(template | page, register)
P(slot | template, line/record position)
P(host form | page, register, slot, prior record state)
P(wrapper | host, slot, register)
P(right/frame | host, wrapper, slot, closure state)
P(DY/B3/line close | template, slot, record state)
```

`PAGE_HOST` is the best current carrier candidate but is not assumed to be a
word.  It may be a graphematic family, abbreviation kernel, code address, or a
mixture.  Exact host identity is useful but insufficient: GDT276 strongly
prefers compiler-conditioned character form to exact host identity, and
GDT165--167 show that partner/context geometry is mostly register-local.

## Why this model leads

- GDT276: compiler-conditioned host character form beats exact host, page
  codebook and previous-host hybrid worlds.
- GDT277--278: that signature is not architecture-specific, but real medieval
  diplomatic text can reproduce its magnitude only in native document order.
- GDT281: Latin controls are RIGHT_FAMILY-led; Voynich is OUTER_WRAPPER-led.
- GDT282: wrapper identity transfers across folios, sections and hands; q is
  exactly one redundant wrapper class, not a second independent feature.
- GDT283--285: wrapper information is strongest at host onset, while the
  terminal penalty depends on recurrent exact-host training support.
- GDT286: wrapper is better predicted from host plus field position than from
  host alone.
- GDT287: the best exposed joint factorization is HOST_FIRST_CONTEXTUAL,
  whereas all three Latin diplomatic controls prefer WRAPPER_FIRST.

This combination is more coherent under a hybrid record shorthand than under
ordinary abbreviated prose or a fixed Cartesian codebook.

## Awkward observations

- The GDT287 lead over WRAPPER_FIRST is only 0.0314 bits/event and post-hoc.
- GDT286's strict null changes only 411/8,448 Voynich IDs; identity-specific
  excess over its null mean is only 0.0123 bits/event.
- GDT285's equal-volume donor control uses its coarsest match for 50.7% of
  Voynich donor events.
- Exact host neighbors fail manuscript-global transfer, so a conventional
  stable lexicon is not recovered.
- Historical controls show that neither compiler-conditioned form nor
  contextual factorization uniquely identifies language, abbreviation, or
  notation.
- There is still no admissible string-to-referent anchor.

## Novel predictions

These predictions were not used to choose the theory:

1. For recurrent hosts observed in several field positions, wrapper shifts
   should follow a low-complexity position-conditioned rule across held host
   families; a large exception table would weaken the model.
2. Once host and field position are known, RIGHT_FAMILY should add more
   information about closure/next field shape than about external content.
3. Exact host recurrence should improve within-group completion but should not
   restore immediate NEXT_HOST prediction across folios.
4. Homologous independently identified records should preserve slot/renderer/
   closure tuples better than exact surface-group sequences.
5. A real historical technical shorthand with layout-conditioned abbreviation
   should approach the Voynich HOST_FIRST_CONTEXTUAL factorization; ordinary
   diplomatic prose should remain WRAPPER_FIRST.
6. Any future translation key must decode latent payload while leaving the
   compiler layers many-to-one; a one-to-one whole-group dictionary should
   continue to fail.
