# GDT553 method

## Question

Can the complete GDT548 145-card prose reader and the four disjoint
GDT549–GDT552 repair generations be compiled into one exact-key zero-rest
working edition without losing any recipe, context slot, meaning or scope
limit?

## Inputs

- GDT548 unified 145-card reader and its 23-card queue;
- GDT549's four current-peer promotions;
- GDT550's ten recurrent-frame promotions;
- GDT551's four context-contract promotions;
- GDT552's five boundary/family promotions.

The four promotion sets must be pairwise disjoint and their union must equal
the original 23-card queue exactly.

## Compilation

Copy every semantic and context field byte-for-byte from GDT548. For the 122
cards outside its queue, retain the original tier route, evidence and caution.
For each queued card, attach exactly one later resolution:

```text
GDT549  current context/interface peer                  4
GDT550  recurrent visible frame + same-mode peers      10
GDT551  action/argument slot-contract normalization     4
GDT552  target-specific boundary/family bridge          5
```

Each repaired card receives the later exact visible trace, the concrete
evidence trace and a scope limit that keeps current-peer locality, absent old
whole recipes, nonlexical input states, or absent direct old pairs visible.
Set `support_rest_status` to none only if every one of the 145 exact keys has a
bounded current route and all preservation checks pass.

Compile an executable exact-key reader with the unchanged GDT540 context
resolution rule. Unknown surfaces stop and inherit no nearby card.

## Decision rule and claim ceiling

Pass only if the source sets partition 145 as 122+4+10+4+5, every recipe and
meaning is unchanged, all 23 former queue cards have exactly one resolution,
all 145 support-rest fields are empty, and the reader replays exact/contextual
and unknown-key probes deterministically.

“Zero rest” means no presently named support task remains inside this admitted
145-card working edition. It does not mean decipherment, confirmed lexemes,
plaintext, language, cipher, phonetic values, historical codebook identity,
object identification or permission to read an unknown spelling. No page,
surface, recipe, segmentation or root meaning changes.
