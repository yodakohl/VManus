# GDT535 method

## Question

Can the other q-initial cards in `qef`'s exact statement decide between
noncarrier `E+LOCAL_CHAR_F` and carrier `CARRIER_Q+E+LOCAL_CHAR_F`?

## Inputs

- GDT407's 4,576 old events for statement-level q-role families.
- GDT516's 597 current events and complete G515-S010 statement.
- GDT522's old visible-q edit signature.
- GDT523's first-atom q context and executable `qe→e~E` path.
- GDT529's four finite `qef` candidates.
- GDT534's complete working edition and executable intake.

No new page is used; `f84` and `f84r` remain forbidden.

## Method

Every q-initial event is labeled only by whether its recipe begins with
`CARRIER_Q`. For each statement with at least two q events, remove one event
from the local vote; when all remaining q events have the same role, record
that role and whether it matches the removed event. This measures whether q
role tends to stay coherent inside one statement without assuming global q
nullity.

For G515-S010, remove `qef` and use its six remaining q events as the local
vote. Compare the result with all four finite candidates, the old 75/84
visible-q null relation, the old 1/1 E-edge context, and GDT523's `qe→e~E`
renderer path. Select only the unique candidate matching all layers.

## Decision rule and claim ceiling

Resolve `qef` as noncarrier only if its six same-statement neighbours are
unanimous, the old q-null and E-edge relations point the same way, and exactly
one finite candidate has the predicted role. Do not change any other recipe.

This is a local q-role closure and concrete working phrase. It does not make q
globally null or establish a confirmed lexeme, plaintext, language, codebook,
object identity, or unopened-page reading.
