# GDT468 method

## Question

Which GDT467 shell recipes already have carriers in the admitted running or
address material, and which are currently only readable compositions of old
channels?

## Inputs

- the 2,760-shell/2,300-recipe GDT467 phrasebook;
- GDT407's 4,576 running events with exact invariant recipes;
- GDT466's 107 exact address labels and corrected function traces.

## Method

Join each flattened shell recipe to exact GDT407 `component_recipe` values and
to GDT466 `ordered_function_recipe_trace` values. Address matches are kept in
two layers: complete function formulae and function traces that cross learned
name cores.

Assign the first available tier:

1. `RUNNING_EXACT_RECIPE`;
2. `ADDRESS_FULL_FORMULA_ONLY`;
3. `ADDRESS_HYBRID_SHELL_ONLY`;
4. `COMPOSITION_ONLY`.

Within tiers, rank by running pages, events, full-address carriers, hybrid
carriers, visible factorization count and recipe string. Propagate the tier to
all 2,760 shell templates. Rank the 423 repeated-recipe factorization families
by the same shared recipe support and retain every exact surface/channel trace.

## Decision rule and claim ceiling

Old-carrier support raises the practical priority of a reading but does not
confirm its German values. `COMPOSITION_ONLY` is an exploratory drawer, not a
rejection: the shell remains executable after it is visibly supplied, but no
old whole recipe currently backs it.

Address hybrid traces are not misreported as contiguous exact manuscript
recipes. No surface is generated and no occurrence is predicted. No new page,
channel, component meaning, object name, plaintext, language or confirmed
lexeme is added.
