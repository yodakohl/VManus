# GDT399 method — rebuild scope from visible recipes

## Question

After Pass 1026 visibly resegmented 203 formerly one-edit-copied surfaces, can
the complete 627-statement workshop edition be rebuilt without changing a core
value, looking ahead more than one card, crossing an owner boundary, or adding
a coarse scope family?

## Inputs

- Pass 1026 supplies the corrected 3,888-event recipe ledger.
- Pass 1018 supplies only the fixed 627 statement boundaries and visible owner
  descriptions.
- Pass 1020 supplies the 31 already selected atom categories.
- Pass 1009 supplies the 22-page physical inventory, including local labels.
- Pass 1025 supplies the superseded baseline used only for deltas.

No raw transcription or new manuscript page is opened by the runner.

## Compiler

For every visible occurrence of `AIIN AIN OR Y E EE EEE AL AR L AIR`, choose
one governor:

1. ordinary arguments and grades choose the nearest same-card action, with a
   left tie;
2. `AL/AR` use left → active inherited head → same-card right → owner;
3. `L/AIR` use right → left → inherited head;
4. a headless package may use the first action on exactly the next card unless
   `DY`, `OS`, or a real statement boundary closes it;
5. `R` is head, tail, or nested by its already selected positional rule;
6. immediate `OR+OR` is package descent; the other repeated focus pairs are
   peer plurality/repetition;
7. every statement resets the action stack and no owner boundary may be
   crossed.

The compiler then rebuilds event, statement, page, register, rule-support, and
96-statement change tables from scratch.

## Decision

The creative model survives this repair only if all 3,888 events and all focus
atoms occur exactly once, every attachment resolves, lookahead is at most one,
owner crossings are zero, one visible surface has one recipe, all nine old
coarse rule families have outside-page and outside-register support, and all
four register holdouts compile without a new category or rule.

## Claim ceiling

This is a consistency result inside the creative working reconstruction. It
does not confirm a plaintext word, language, translation, or historical code.
