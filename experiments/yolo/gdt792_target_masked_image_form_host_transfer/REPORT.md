# GDT792 report — target-masked image/form host transfer

## Result

GDT792 produces one useful structural correction and no translation.

`okal` is selected as `CROSS_SCOPE_LABEL_PROSE_WHOLE`: the same complete form
occurs as four singleton labels on three pages/two visible topologies and as
sixteen running-text tokens. It is not selected as
`Ziel-/Bezugsstelle`, `Stellenkennung oder Klasse`, `adressiertes Mitglied`,
name, grade or number. Those meanings remain explicit C0 rivals.

The earlier GDT734 `okal` heat/material/grade default is quarantined at the
fifteen released-scope positions where that cache actually contains an `okal`
cell. Five additional occurrences were not GDT734 cache cells and receive only
a new structural overlay. No row emits German semantic prose.

Validation passes 257 checks, two byte-identical builder replays, exact source
hashes and a replay of the GDT388 relation-packet intake.

## What `okal` really establishes

Fifteen of sixteen running occurrences are physically line-internal. The
outside partition has 13/14 internal uses and predicts that role; both held
running uses are internal. Four local uses are singleton lines. Outside labels
occur on f67r and twice on f72r; the held label occurs on f82r, introducing the
pool/apparatus topology after radial-array labels.

In the all-30 descriptive ranking, `okal` ranks first by singleton-label page
breadth, topology breadth and count. That rank is not a target-masked selection
statistic: when the same ordering is computed from only the 27 outside pages,
`okal` ranks fourth, or second after single-EVA-character forms are excluded.

Likewise, its line-internal rate beats eight of eight controls in both
deterministic decks, but the decks overlap on seven forms and contain only nine
unique controls in total. They are sensitivity views, not two independent
confirmations.

Most importantly, the 60% host-transfer rule is easy for this corpus. Among
139 recurrent forms for which the outside-to-held role is testable, 105 pass;
95 of 119 forms predicted to be line-internal pass. `okal` is unusual chiefly
because it combines running use with four singleton labels, not because an
internal-line role by itself reveals a word meaning.

## Why the proposed address gloss is withheld

The preregistered raw observations all occur, but they do not distinguish the
registered semantic candidates:

- an address or reference site;
- a label or class identifier;
- the member addressed by a label;
- a name, grade or number;
- an opaque member of the productive `okal*` form family.

The two new f72 label-to-prose pairs and two retained f82 pairs are exact
complete-whole reuse observations. They form only two page clusters: two f72
labels converge on one prose occurrence, while one f82 label is reused twice
in prose. The GDT388 intake returns
`VALID_ACQUISITION_NOT_SCORE_READY`, with zero eligible edges. Transcription
order is not reference direction, and every edge retains zero semantic credit.

Selecting `Ziel-/Bezugsstelle` from those shared observations would merely
repeat the previous failure mode: choose a preferred gloss first, then score
features that all rival glosses predict equally well. GDT792 records that the
raw preregistered trigger fired but deliberately withholds its semantic
consequence.

## `otedy`: parser closure was not physical closure

All eighteen running `otedy` tokens are final in the inherited GDT581 parser,
but only one is physically line-final. Fifteen are line-internal and two are
line-initial. After GDT791's visible record correction, the set divides into
nine singleton fields and nine attached fields rather than eighteen genuine
record closures.

All running occurrences are Currier-B (17 hand 2, one hand 3), so register and
hand remain strong confounds. Ten of eighteen running occurrences have a
unique, forced exact-token partner in both alternate-reader line alignments.
The f77r label and its next visible-record reuse both survive that diagnostic,
which keeps a local port/conduit-status hypothesis alive. One local port cannot
license that meaning globally. The broader `bounded state/value field` rival
also remains unselected because its strongest regularity is parser-coupled.

## Alternate-reader correction

ZL3b, IT2a and RF1b are three readings of one manuscript, never independent
witnesses. Earlier nth-occurrence matching could claim a correspondence merely
because another identical token existed somewhere on the alternate line.
GDT792 now uses all maximum exact-token line LCS alignments. A target counts as
stable only if every maximum alignment must use it and it has one unique
alternate partner. Across 116 target/reader pairs, 95 are uniquely forced and
21 have no exact alignment. These are transcription-stability diagnostics with
zero independent semantic credit.

## Claim ceiling

GDT792 establishes no plaintext word, clause, language, sound value, free
component, object, substance, number, disease, treatment or unseen-page rule.
It does establish that `okal` should no longer be rendered on these positions
as if the old heat/raw-material story were settled, and it provides an exact
structural cross-scope carrier for the next meaning test.

## Next route

The next experiment must score candidate-specific paragraph/page predictions,
not another generic host feature. It should compare all twenty `okal`
neighbourhoods and the visible `okal*` label family under four explicit models:

1. address/reference: running occurrences should link consistently to a
   previously or locally introduced member/site;
2. class/identifier: variants should partition repeated label classes and
   occupy comparable categorical fields in prose;
3. addressed member: occurrence position should follow local array order or a
   recoverable member-selection relation;
4. grade/number: variants should track ordered visual positions or repeated
   scalar slots.

A candidate earns a concrete renderer default only by predicting a different
whole-paragraph or whole-page pattern from its rivals. In parallel, `otedy`
should be tested as a unique-forced complete whole/span against its `ot-/qot-`
family, with f77 port status remaining local until it transfers.
