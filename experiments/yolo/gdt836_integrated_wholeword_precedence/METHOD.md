## Integrated engine

`build_engine.py` derives the explicit committed decoder from hash-bound GDT834
source. Role counts, positional domains, candidate pools and the OFF language
objective retain their prior meaning. Atomic units, word/paragraph boundaries
and nominal26L/4S/8W capacities remain supplied. No suffix-priority or full
canonical inverse condition is added or claimed.

The proposed comparison exposes RELAXED and STRICT modes. Both use the same
role-blind package initialization and search algorithm. STRICT adds the exact
GDT835 condition: build the current candidate's own W-output→carrier map,
including inactive W entries; any decoded complete word in that map must
originate from the corresponding singleton carrier. The old static Word.W
flag is never used for this check.

For each proposal, all package edits are first applied together, and all
affected decoded words are refreshed. A global scan then compares EVERY cached
decoded word type with ALL current W owners. This catches an inactive W change
that invalidates an otherwise unchanged composed word. Checking only affected
words, changed output strings or a stale decoded cache would be insufficient.

If the priority condition fails, the engine restores all edited packages and
tentative decoded words before edge values, score or best-key state are
committed. Forced acceptance does not override this condition. Greedy moves use
the same path, and restored final best keys are checked. The global cached scan
is checked against fresh direct decoding on invented fixtures.

## Initialization

Initialization proposes feasible role packages using the inherited frequency
and seeded permutation rules. No language objective, decoded cache or best-key
update occurs while testing a proposal. Both modes accept the FIRST directly
W-compatible candidate, under the same explicit initialization seed, with a
cap of1,000 attempts. The accepted state alone initializes caches and best-key
state. The search RNG is then reset to a separate explicit search seed.

The initializer retains GDT834's initial top-eight W-value set while varying
packages/roles/letter assignments; it is not an exhaustive feasibility solver.
Exhausting the cap yields INITIALIZATION_STOP, an operational failure rather
than proof of model impossibility. No cap increase, alternative initializer,
best-of-retries selection or repair is performed. Initial keys, attempt count,
seeds and priority-rejection counts are recorded by the engine. Paired starts
and seeds do not imply identical proposal streams after differing rejections.
