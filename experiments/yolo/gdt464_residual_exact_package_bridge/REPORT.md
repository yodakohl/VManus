## `of` is a technical card, not a stellar name

This is the strongest correction. The exact running card `qof` has recipe
`O+LOCAL_CHAR_F`. Every one of the six bare `of…` running types begins with the
same two atoms (6/6, on five pages):

`ofar`, `ofydy`, `ofshdy`, `ofalsheky`, `ofal`, and `ofchdy`.

That channel occurs in six address labels spanning both celestial and
pharmaceutical material. The mixed class is positive evidence against an
individual star-name reading. It yields, among others:

- `of` → `AUSFÜHRUNG · HIER`;
- `ofaralar` → `AUSFÜHRUNG · HIER · AUSGANG · ZIELORT · AUSGANG`;

The unreconstructed spans remain explicit name cores. In particular, this does
not revive the rejected `om` edge.

## `ainy` is a two-card tail

The suffix `ain` retains `AIN=ANTEIL` in all 53 running extensions (214 events,
20 pages), and `y=POSTEN` is an exact recurrent card. GDT463 independently

- `chdaiirdainy` → `[STERNSTELLENNAME:chdaiird] · ANTEIL · POSTEN`.

No meaning is assigned to `chdaiird`.

## `eey` is not the rejected `ey` edge

The target is terminal `eey`, with exactly two e-positions before `y`. Longer
`eeey` forms are a distinct grade-III channel and are excluded before scoring.
Among the resulting 46 running types, 45 end in `EE+Y` across eighteen pages.
The sole exact whole-card exception is `sorcheey=OR+Y`.

Thus `opoeey` becomes
`[STERNSTELLENNAME:opo] · GRAD II · POSTEN`. The opaque `opo` core is retained;
neither `op` nor `ey` is promoted.

## `yddy` is an overlapping two-arm package

GDT459 had already found the green parse `y|d|dy → Y+D_ADDR+Y`, but its old
two-atom admission cap left the singleton in the whole-label tier. All three
pieces are exact recurrent cards:

- `y=Y` (39 events on seventeen pages);
- `d=D_ADDR` (11 events on eight pages);
- `dy=Y` (44 events on seventeen pages).

More importantly, the left arm `Y+D_ADDR` occurs in thirteen running types and
the right arm `D_ADDR+Y` in 66. The full label can therefore be read without a
new long card: `POSTEN · HIER · POSTEN`.
