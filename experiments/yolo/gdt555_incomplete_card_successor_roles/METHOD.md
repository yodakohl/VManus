# GDT555 method

## Question

Do the 16 no-action and 57 no-argument events isolated by GDT554 become
concrete state initializers when their own GDT539 inheritance links and
same-statement successors are followed, and which residuals instead behave as
nominal, objectless, closure or boundary cards?

## Inputs

- GDT539's 546 contextual events, including exact action/argument source IDs;
- GDT554's semantic event and statement-template atlases.

The two gap sets overlap: every event is counted once in the unique union.
No new page or image is opened.

## Method

For each gap event, retain its existing recipe, macro and German clause. Locate
its immediate predecessor and successor inside the same source statement.
Then collect every later event whose explicit GDT539 inherited-action or
inherited-argument source ID points back to the gap event.

An event with a visible argument but no action is an argument initializer only
when a later same-statement card actually names it as its inherited-argument
source. An event with a visible action but no argument is an action initializer
under the analogous source-ID rule. Record immediate and delayed consumers
separately. Non-sources retain one of the already visible roles: nominal or
scope prologue, carried objectless control, objectless action before reset, or
closure/statement boundary.

Compile a full unique-gap deck, separate 16- and 57-event views, exact
initializer links, role totals and per-surface role profiles. Paired readings
may concatenate the two already published clauses; they may not insert a new
verb, noun or object.

## Decision rule and claim ceiling

Pass as a working classification if the gap sets reproduce 16 and 57 with the
correct overlap and union, every initializer link is an explicit same-statement
GDT539 source pointer, all immediate links go to the next ordinal, every gap
retains its exact GDT554 recipe/macro/clause, and every residual receives a
visible default role.

Initializer and boundary are editorial state-machine roles in the four-page
working edition, not historical word meanings or plaintext. No new root,
recipe, segmentation, German clause, syntax, object, codebook or future-page
license follows.
