# GDT389 pre-freeze f84 metadata-display correction

Before GDT389 was frozen, a broad repository search intended to locate cached
canvas mappings printed one existing single-line JSON artifact because that
artifact also contained an allowed page. The displayed portion included the
already published f84r page identifier and the existing visual document-role
metadata value `REPEATED_OWNED_RECORDS`.

This was a real process breach of the user's no-display instruction. No f84
image, transcription, source group, surface form, formal family, PAGE_HOST,
joint tuple, prediction, or score was opened. The metadata was not used to
select a page, define a relation, tune a method, or score an outcome.

GDT389 repairs the loader before any image review:

- its only page universe is the exact f84-free GDT388 page-frame artifact;
- public image metadata must be filtered by an exact allowed page label before
  any other field is retained;
- any canvas whose label mixes an allowed page with an f84 page is rejected;
- no repository-global canvas search is permitted; and
- the final validation must bind the allow-list and prove that every retained
  page, canvas label, image, observation, and endpoint is f84-free.

No further f84 access is authorized. The surprise holdout is no longer pristine
with respect to this one already public visual-role metadata value, but its
image and all formal/text payload remain unaccessed in this pass.
