# GDT523 method

## Question

Can GDT522's visible-to-null edit families license an explicit renderer-path
insertion even when deleting that visible block does not leave a separately
known old surface?

## Inputs

- GDT407's 1,558 invariant old surface recipes;
- GDT516's 159 current benchmark forms;
- GDT522's finite candidate scores and local edit inventory;
- GDT520's selected monotone renderer paths.

No new page is admitted.

## Path insertion

For each renderer path part, delete one to three contiguous visible characters
from its surface segment. A path-null option exists only when this deletion
exactly recovers the selected renderer alias. Substitution, a missing alias
character or a noncontiguous deletion does not qualify.

The current experiment activates only a left-edge visible insertion. Its
GDT522 null mapping must have positive global smoothed log odds. The same
visible insertion must also have positive null log odds when conditioned on
the first atom of the base recipe. This separates, for example:

```text
q before OK: 33 null / 1 other relation
q before O:   4 null / 7 other relations
```

The selected feature is deliberately small:

```text
reliability = null support / (null support + 2)
feature = reliability * recovered visible edit width
GDT523 score = GDT522 score - 0.25 * feature
```

The broader ladder also tests null log odds alone and edit width plus log odds.
Those rows are diagnostic alternatives, not hidden defaults.

## Rehearsal and ceiling

Each old SHA-256 fold rebuilds GDT521, GDT522, the renderer deck, boundary
model and atom-conditioned null gate from the other three groups. Exact-event
and known surface/role cards retain precedence.

The path feature licenses a visible renderer expansion. It is neither a claim
that the character has no meaning in every context nor a word translation.
