# GDT1166 — natural shared-sign candidate control

Status: **REGISTERED_UNSCORED; no real-source fit or recovery result yet.**

A fixed source-only test asks whether a shared opaque writing channel can generate expansion candidates for previously unseen abbreviated B4 word types from the other five CoReMA witnesses. The three arms share one finite 32-key panel: literal output, a constant per-mark residual, and a variable residual. This is not a Voynich translation or a complete historical writer model.

The governing files are [METHOD.md](METHOD.md), [SPEC.json](SPEC.json), [PREPARATION.md](PREPARATION.md), and [VALIDATION_PLAN.md](VALIDATION_PLAN.md). Original source bytes and provenance are bound by [src/SOURCE.json](src/SOURCE.json). Public-registration and subsequent stage authorization belong in their release receipts; no commit or authorization is asserted here in advance.

## Stage releases and exact fit commands

After public preregistration, root supplies `artifacts/FIT_RELEASE.json` with status `FIT_RELEASED`, the registered commit and relative-path SHA256 bindings. It is an authorization receipt, not generated by the fitting command. The fitter checks those bindings before opening only `artifacts/TRAIN_INPUT.json` and `artifacts/REFERENCE_INPUT.json`.

```bash
python3 experiments/yolo/gdt1166_natural_shared_sign_candidate_control/src/run.py --stage fit --runtime "$gdt1166_runtime"
```

This emits `KEY_PANEL.json.gz`, `SEARCH_SCORES.json.gz`, `KEY_SELECTION.json`, and `KEY_SELECTION_LOCK.json`. All 32 states, finite search scores and selected-score ties are retained. No held input or gold is opened by this stage. Compiled binaries and temporary numerical files stay in the chosen runtime directory, outside public artifacts.

Only after the key lock is checked, root supplies `artifacts/PREDICTION_RELEASE.json` with status `PREDICTION_RELEASED` and `key_lock_sha256`.

```bash
python3 experiments/yolo/gdt1166_natural_shared_sign_candidate_control/src/run.py --stage predict --runtime "$gdt1166_runtime"
```

This first opens `HOLDOUT_INPUT.json`, retains complete compatible candidate rankings for every held written type, and writes `PREDICTIONS.json.gz` plus `PREDICTION_LOCK.json`. No gold is opened. Unknown/unfit atoms receive empty predictions; no free frequency candidates fill empty lists.
