# GDT1093 method

## Question and frozen rule

The preregistration fixes the 309-canvas Egerton 747 deck and three f25v
features. A source entry is a strict owner only when all three features are
visually YES on the same authorially named plant. An UNCLEAR fails the strict
rule. This is a source-image screen, not a Voynich text or translation test.

## Sources and procedure

`src/fetch_source_deck.py` verifies the official BL IIIF manifest digest,
downloads each canvas at 320px, and writes `src/SOURCE_DECK.tsv` with each
thumbnail URL, byte count and SHA-256. All eight contact sheets were examined.
Eight potentially informative named entries, including the two already
examined before registration, were inspected at 1500px and recorded in
`src/NATIVE_SHORTLIST.tsv`. Seven images were downloaded anew; f89r was
already viewed and documented in the predecessor note. The high-resolution
visual judgments are human observations; the code checks roster and decision
consistency, not the image interpretation.

## Limits

The 320px first pass may conceal minute details outside the selected entries.
The complete image roster is auditable, but this is not an exhaustive OCR or
transcription of Egerton headings. The f25v image was already known; the
comparison is exploratory and cannot supply independent Voynich confirmation.
The later Rabarbarum resemblance is disclosed without changing the fixed
three-feature rule.
