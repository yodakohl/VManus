# GDT438 method

## Question

Can GDT437's written-order repair be integrated into the oracle-free GDT436
streaming reader without changing state, meanings or stop behavior?

## Inputs

- GDT415's ordered 4,576 events and 715 statement memberships;
- GDT436's state driver and complete baseline replay;
- GDT437's order-safe renderer, exhaustive transition matrix and 68 expected
  current-event repairs;
- GDT434's exact 1,563-recipe intake catalog.

## Method

Run the GDT436 page-owner state banks unchanged. After a licensed card's
explicit and inherited action/argument fields have been determined, render its
clause through GDT437. Rebuild all current statements. Then feed all 49 main
future cards through the command in all five registers, using an ordinary
preceding `OK+Y` card to establish state; these inputs contain no event IDs.
Finally, verify that unseen-atom and unlicensed-known-atom stops do not mutate
the bank.

## Decision rule and claim ceiling

Pass only if all 4,576 states match GDT436, all clauses match GDT437, exactly
the expected 68 events/59 statements change order, all 245 prospective probes
match the transition matrix, and both stop types preserve state. This is an
integration result inside the working model, not independent evidence for a
meaning, plaintext, language, surface or page.
