# GDT460 — learned label edge stem atlas

## Result

The 107 GDT459 whole labels are not 107 equally opaque words. They have the
architecture expected from a mixed technical codebook/nomenclator:

| hybrid status | labels | working interpretation |
|---|---:|---|
| fully edge-readable formula | 5 | no learned middle remains |
| functional edge + learned name core | 78 | known instruction/address frame around a name |
| replicated owner-family marker only | 5 | content family visible, function edge absent |
| whole learned label | 19 | memorize complete form |

Eighty-three labels carry a calibrated functional prefix or suffix. Seventeen
replicated owner-family substrings touch 35 labels. Their union gives visible
structure to 88/107 labels; only 19 remain wholly unstructured. The calibrated
edges account for 277/713 written characters (38.85%) without assigning the
middle strings invented meanings.

## The functional stem deck

Twenty-four unique surface stems survive as 27 directional channels. The
strongest prefix channels are:

- `ot → DANACH`: 66/66 matching running extension types; 21 learned labels;
- `ok → SETZEN`: 80/81; 13 labels;
- `ol → FORTSETZEN`: 54/56; 6 labels;
- `or → EINHEIT`: 11/11; 5 labels;
- `otal → DANACH · ZIELORT`: 4/4; 3 labels;
- `otol → DANACH · FORTSETZEN`: 4/4; 5 labels.

The strongest suffix channels include:

- `aiin → WERT`: 89/89 running extension types; 9 labels;
- `ain → ANTEIL`: 53/53; 3 labels;
- `am → HIER`: 25/26; 12 labels;
- `ar → AUSGANG`: 84/86; 7 labels;
- `al → ZIELORT`: 78/81; 11 labels;
- `aly → ZIELORT · POSTEN`: 20/20; 4 labels;
- `cthy → NEHMEN · EINSTELLEN · POSTEN`: 12/12; one label.

Direction matters. `or` at the left and right edge has the same current value,
but it is stored as two independently calibrated channels. A middle occurrence
does not inherit either channel automatically.

## Five complete recovered formulae

The longest nonoverlapping edge rule fully covers five former whole labels:

- `alcphy = AL + CPHY` → `ZIELORT · NEHMEN · EINSETZEN · POSTEN`;
- `otalaiin = OTAL + AIIN` → `DANACH · ZIELORT · WERT`;
- `otolam = OTOL + AM` → `DANACH · FORTSETZEN · HIER`;
- `alaly = AL + ALY` → `ZIELORT · ZIELORT · POSTEN`;
- `otolaiin = OTOL + AIIN` → `DANACH · FORTSETZEN · WERT`.

These are the clearest demonstration that the local-label stream contains
ordinary technical formulae interleaved with learned names.

## Hybrid examples

Most labels are neither completely formulaic nor completely opaque:

- `okaraiin` reads `SETZEN · [STERNSTELLENNAME: ar] · WERT`;
- `otolaiin` loses its middle entirely and becomes a full formula;
- `otorain` reads `DANACH · [DROGENNAME: or] · ANTEIL`;
- `opalar` retains `[STERNSTELLENNAME: opal] · AUSGANG`;
- `daramdal` retains `[DROGENNAME: daram] · ZIELORT`.

The bracketed middle is deliberately copied, not translated. This is the
usable codebook rule: translate the verified technical shell and learn the
content name from the exemplar.

## Replicated nomenclator families

Seventeen internal substrings recur in at least three labels, exclusively in
one owner class, and on both current pages of that class. The drug side has
three compact families:

- `otora`: `otoram`, `otora`, `otorain`;
- `dara`: `daramdal`, `dararda`, `sydarary`;
- `arar`: `dararda`, `ararchodaiin`, `sydarary`.

The stellar side contains fourteen markers, led by `ala` (9 labels), `tal`
(5), and the `raii/raiin`, `kar/kara/okar`, `opal`, `otal`, `otch`, and `sho`
families. Their safe working values are only `DROGENFAMILIE` and
`STERNSTELLENFAMILIE`. Some may ultimately prove to be technical frames rather
than noun stems; either way they already predict which local deck a new form
belongs to.

## New working model

The strongest compositional model is now:

> functional prefix + learned name core + functional suffix,
> with a smaller set of fully formulaic cards and a still smaller set of
> indivisible nomenclator entries.

That is a closer historical analogue to a mixed technical abbreviation system
and nomenclator than either a fully phonetic word list or 107 unrelated code
groups.
