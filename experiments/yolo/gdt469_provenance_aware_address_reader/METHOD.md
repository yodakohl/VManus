# GDT469 method

## Question

Can GDT468 recipe provenance be attached to every GDT466 intake result without
changing the selected channels, learned cores, family route or working reading?

## Inputs

- GDT466's 44 function channels, eighteen family markers, 107 exact labels,
  intake implementation and 81 complete branch probes;
- GDT467's 8,280 bounded-shell executions;
- GDT468's 2,300 recipe support rows and 2,760 supported shell templates.

## Method

Run the unchanged GDT466 intake first. For an unseen surface, reconstruct its
exact ordered GDT466 channel IDs. Join that exact signature to the bounded shell
phrasebook and join the flattened component recipe to the GDT468 support atlas.
Return the base reading plus shell ID/template, support tier/rank and old
running/address carrier counts. Exact known labels retain first precedence and
are not rematched as synthetic shells; their function trace may still receive a
recipe tier.

Replay all 107 exact labels, all 8,280 GDT467 shell probes and all 81 GDT466
branch probes. A replay passes only if the base route and reading are unchanged
and every expected shell tier/signature/rank is reproduced.

## Decision rule and claim ceiling

Provenance may label a reading as running-backed, complete-address-only,
hybrid-shell-only, composition-only, or outside the bounded shell atlas. It may
never override the base intake result. Outside-atlas does not erase a known
exact label or force a new segmentation.

No new page, channel, component meaning, surface prediction, occurrence,
object name, plaintext, language or confirmed lexeme is added.
